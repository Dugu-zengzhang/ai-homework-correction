## 三、分支策略与提交规范落地情况

### 3.1 开发过程文档中的规范（原定）

开发过程文档（一）中规定的分支策略与提交规范如下：

| 规范项 | 原定标准 |
|--------|---------|
| 分支模型 | main（稳定）+ dev（开发）+ feature/*（功能分支） |
| 合并方式 | feature → dev → main，经 Code Review 后合并 |
| 提交信息格式 | `<type>(<scope>): <description>`（如 `feat(auth): 添加 JWT 鉴权`） |
| 类型枚举 | feat / fix / docs / chore / refactor / test |

### 3.2 实际执行情况（如实记录）

| 规范项 | 实际执行 | 偏差说明 |
|--------|---------|---------|
| 分支模型 | **仅使用 `main` 单分支**，未创建 dev / feature 分支 | 小组 4 人均在本地开发后直接提交到 main，未走分支合并流程 |
| 提交信息格式 | **部分遵循**：`517a125` 使用了 `chore(project):` 前缀，`5e53a92` 使用了 `docs:` 前缀；但 `85e8d81` ~ `1bbf603` 三条提交信息均为"第四次实验任务卡片的上传"，未使用规范前缀 | 后三条为同一文件的迭代修订，提交者未严格按规范填写信息 |
| Code Review | 未在 GitHub 上使用 Pull Request 流程 | 代码评审以线下交叉走查方式进行，评审记录见代码评审过程文档 |
| 合并方式 | 无合并操作（单分支直接 commit） | — |

### 3.3 偏差原因与改进计划

| 偏差 | 原因 | 改进计划（V1.1） |
|------|------|-----------------|
| 未使用 feature 分支 | V1.0 阶段 4 人分工明确、各自负责模块独立，直接提交 main 效率更高；项目规模（~1500 行）未达到分支管理的收益阈值 | V1.1 引入爬虫与云端 OCR 等较大改动后，将启用 feature 分支 |
| 提交信息不规范 | 后三条为快速迭代修订任务卡片，提交者未注意格式 | 后续提交统一使用 `docs(scope): description` 格式 |
| 未用 PR 流程 | 小组在线下集中评审，GitHub PR 会增加不必要的操作开销 | V1.1 若改为远程协作，将启用 PR |

## 四、.gitignore 安全策略说明

### 4.1 忽略规则总览

`.gitignore` 文件共 7 个分区，覆盖以下类别：

| 分区 | 忽略内容 | 忽略原因 |
|------|---------|---------|
| 1. 敏感 & 运行时配置 | `api_key.txt`、`.env*`、`data/settings.json`、`data/.secret_key`、`data/ai-homework-check_secret.key` | 含 DeepSeek API Key、JWT 密钥等敏感信息，**绝对不能入库** |
| 2. 运行时数据库 / 缓存 | `data/app.db`、`data/app.db-journal`、`data/rag_index.json`、`data/uploads/`、`data/knowledge/uploaded/` | 本地动态生成，含用户作业图片与学生数据，入库无意义且涉及隐私 |
| 3. Python 字节码 / 缓存 | `__pycache__/`、`*.pyc`、`.venv/` 等 | 编译产物与虚拟环境，每人机器不同 |
| 4. pytest / 覆盖率报告 | `.pytest_cache/`、`htmlcov/`、`.coverage` | 测试产物，不入库 |
| 5. 编辑器 / IDE | `.idea/`、`.vscode/`、`*.swp` 等 | 个人编辑器配置，每人不同 |
| 6. 操作系统缓存 | `Thumbs.db`、`.DS_Store` 等 | 系统自动生成 |
| 7. 临时日志 / 调试 | `*.log`、`logs/`、`*.bak`、`*.tmp` | 运行日志与临时文件 |

### 4.2 被忽略的敏感项清单（审批重点）

| 文件 | 内容 | 入库风险 | 忽略规则 |
|------|------|---------|---------|
| `api_key.txt` | DeepSeek API Key 明文 | 泄露后他人可盗用 API 额度 | `api_key.txt` |
| `data/settings.json` | 管理员后台配置（含 API Key、模型名、接口地址） | 同上 | `data/settings.json` |
| `data/.secret_key` | JWT 签名密钥 | 泄露后可伪造登录令牌 | `data/.secret_key` |
| `data/app.db` | SQLite 数据库（含用户密码哈希、学生作业记录） | 泄露用户数据 | `data/app.db` |
| `data/uploads/` | 学生上传的作业图片 | 涉及学生隐私 | `data/uploads/` |
| `data/knowledge/uploaded/` | 爬虫审核入库的习题（版权素材） | 涉及版权 | `data/knowledge/uploaded/` |

### 4.3 验证：敏感文件未入库

在本地执行 `git status` 确认上述文件均显示为 ignored 或 untracked，未出现在暂存区。仓库 GitHub 页面确认 `data/` 目录下仅有 `knowledge/` 根目录的示例文件，无 `.db`、`.json`（rag_index）、`.secret_key` 等文件。
